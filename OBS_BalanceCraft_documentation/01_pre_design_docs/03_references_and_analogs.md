# 03. Аналоги, референсы и адаптация решений

## Цель раздела

Задача анализа аналогов — не доказать, что BalanceCraft “лучше всех”, а понять:

1. какие задачи уже закрывают существующие инструменты;
2. какие паттерны стоит перенять;
3. где остаётся ниша BalanceCraft;
4. что нельзя копировать, чтобы не превратить продукт в клон чужой системы.

## Критерии сравнения

| Критерий | Что оценивается |
|---|---|
| Основной фокус | маркетинг, продуктовая аналитика, баланс, моделирование |
| Источник данных | SDK, платформа, локальные логи, ручная модель |
| Пользовательские события | насколько гибко задаются события |
| Работа с параметрами игры | можно ли анализировать цены, награды, лимиты, шансы |
| Шаблоны метрик | есть ли готовые сценарии анализа |
| What-if / моделирование | можно ли проверять изменения до внедрения |
| Покрытие проблем баланса | показывает ли инструмент, какие симптомы можно проверить по текущим данным |
| Локальность | можно ли работать без облака |
| Простота для инди | насколько легко внедрить без аналитика |
| Privacy posture | куда уходят данные |

## Steamworks

### Что закрывает

Steamworks полезен как платформенный источник отчётов: продажи, вишлисты, UTM-кампании, трафик, эффективность внешних переходов.

### Что можно перенять

- Простые отчёты, понятные без аналитика.
- Breakdown по источникам и результатам.
- Ясную связь “источник → действие → результат”.
- Стиль “не заставлять пользователя строить всё с нуля”.

### Что не копируется

- Маркетинговый фокус.
- Привязка к платформе.
- Аналитика продаж как основной смысл продукта.

## Unity Analytics

### Что закрывает

Unity Analytics даёт события, дашборды, метрики поведения, фильтры, engagement, progression, spending и другие продуктовые срезы.

### Что можно перенять

- Событийный подход.
- Дашборды с быстрым обзором.
- Фильтры по параметрам и группам.
- Идею готовых представлений поверх raw-events.

### Что не копируется

- Облачная зависимость.
- Фокус на поведении пользователя вместо баланса системы.
- Привязка к конкретной экосистеме как обязательный путь.

## GameAnalytics

### Что закрывает

GameAnalytics ближе всего к BalanceCraft по игровой аналитике: custom/design events, dashboards, funnels, retention, progression-срезы.

### Что можно перенять

- Разделение стандартных и пользовательских событий.
- Custom dashboards.
- Понятный event taxonomy.
- Быстрые готовые обзоры для пользователя.
- Идею “события должны быть полезны для дизайнерских вопросов”.

### Что не копируется

- Внешняя платформа как обязательная инфраструктура.
- Маркетингово-продуктовая рамка как центр продукта.
- Слабая работа с параметрами игры как изменяемыми рычагами баланса.

## Machinations

### Что закрывает

Machinations — инструмент моделирования и симуляции игровых экономик: визуальные схемы, сценарии, Monte Carlo, digital twins.

### Что можно перенять

- Идею безопасной проверки изменений до релиза.
- Разделение параметров, потоков и результатов.
- Показ неопределённости и сценариев.
- Мышление “система баланса как модель”.

### Что не копируется

- Полноценный визуальный редактор экономических моделей.
- Требование вручную строить модель всей игры.
- Сложность, которая может отпугнуть инди-пользователя на первом запуске.

## Таблица референсных решений и адаптации

| Источник | Решение | Зачем полезно | Как адаптировать в BalanceCraft | Что не копировать |
|---|---|---|---|---|
| Steamworks | понятные отчёты и breakdown | быстро понять источник результата | простые сводки импорта, билдов, шаблонов | маркетинговую рамку |
| Unity Analytics | events + dashboards | привычная модель аналитики | карта событий, фильтры, готовые графики | облачную зависимость |
| GameAnalytics | design/custom events | подходит к игровым действиям | custom event profiling и шаблоны анализа | платформенность |
| GameAnalytics | custom dashboards | пользователь хочет свой обзор | сохранённые views и наборы метрик | перегруженный BI-интерфейс |
| Unity / GameAnalytics | event taxonomy | события должны отвечать на вопросы дизайна | рекомендуемый словарь событий для источников, трат, блокировок, наград и usage | жёсткую платформенную схему |
| Machinations | сценарное мышление | проверка изменений до внедрения | многоуровневый What-if | полный визуальный симулятор в MVP |
| Machinations | Monte Carlo / uncertainty | честность сценарных выводов | статусы уверенности и диапазоны | обещание точности без модели |

## Позиционирование

BalanceCraft занимает нишу между продуктовой аналитикой и симулятором экономики.

```text
GameAnalytics / Unity Analytics показывают, что игроки делали.
Machinations помогает моделировать экономику до или отдельно от игры.
BalanceCraft должен помогать понять числовой баланс по событиям игры,
связать наблюдаемую телеметрию с параметрами, которые можно изменить,
и честно показать, какие проблемы текущий набор данных позволяет анализировать.
```
