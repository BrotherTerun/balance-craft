# 07. Принципы работы с телеметрией и данными

## Назначение

BalanceCraft предназначен для анализа числового баланса игровых систем на основе событийной телеметрии. Система не должна использоваться для скрытого сбора персональных данных игроков.

Версия 1.5 проектируется как local-first инструмент.

## Режимы работы

| Режим | Статус | Данные хранятся |
|---|---|---|
| Local Mode | основной для 1.5 | на машине пользователя |
| Self-hosted Collector | будущая версия | на сервере разработчика игры |
| BalanceCraft Cloud | отклонённая альтернатива, не входит в реализуемые версии | не используется |

## Local Mode

Схема:

```text
игра / тестовая сборка
→ локальная запись JSONL
→ ручной импорт в BalanceCraft Desktop
→ локальный анализ
```

Правила:

- сервер не используется;
- данные не отправляются авторам BalanceCraft;
- Desktop работает с файлами, выбранными пользователем;
- ответственность за содержимое файлов несёт пользователь инструмента;
- SDK не должен добавлять персональные поля автоматически.

## Self-hosted Collector

Схема:

```text
игра
→ SDK
→ локальный кэш
→ сервер разработчика игры
→ экспорт
→ BalanceCraft Desktop
```

Сервер принадлежит разработчику игры. Авторы BalanceCraft не получают доступ к данным, если разработчик сам их не передал.

Разработчик игры отвечает за:

- privacy policy;
- правовое основание обработки;
- уведомление пользователя;
- отказ от аналитики, если он требуется;
- retention policy;
- безопасность сервера;
- обработку инцидентов.

## Допустимые данные по умолчанию

```text
event_type
timestamp
entity_id / псевдонимный идентификатор сущности
observation_id / окно анализа
observation_type
build_id / версия игры
schema_version
числовые игровые параметры
категориальные игровые параметры: режим, уровень, сложность, тип действия
```

## Недопустимые данные по умолчанию

```text
имя игрока
email
открытый SteamID или другой платформенный ID
IP-адрес как аналитическое поле
платёжные данные
личные сообщения
пользовательский текстовый ввод
полное содержимое сохранения
точная геолокация
```

Главное правило:

```text
Если поле не нужно для анализа баланса, SDK и Collector не должны его собирать.
```

## Псевдонимизация

BalanceCraft должен работать с псевдонимными идентификаторами:

```text
installation_id
playthrough_id
entity_id
observation_id
```

Эти идентификаторы не должны напрямую раскрывать личность игрока.

Корректные формулировки:

- псевдонимизированные данные;
- обезличенная игровая телеметрия;
- данные без прямых персональных идентификаторов.

Не следует обещать полную анонимность, если данные теоретически можно связать с пользователем через другие источники.

## Требования к SDK

SDK должен:

- предоставлять `TrackEvent` / `Track`;
- автоматически добавлять `timestamp`;
- поддерживать `entity_id` и `observation_id`;
- писать события локально;
- буферизовать события при отсутствии интернета;
- отправлять батчи только при включённой аналитике и настроенном endpoint;
- не блокировать игровой процесс;
- не падать вместе с игрой при ошибке отправки;
- ограничивать размер локального кэша;
- не собирать персональные данные автоматически.

SDK не должен:

- хардкодить сервер авторов BalanceCraft;
- отправлять данные без настройки разработчика игры;
- отправлять события, если аналитика выключена;
- собирать SteamID, email, имя игрока или IP как часть event payload;
- читать сохранения целиком;
- собирать пользовательский текстовый ввод без отдельного решения разработчика.

## Требования к Self-hosted Collector

Collector должен:

- принимать данные только по HTTPS;
- использовать project token / API key;
- валидировать схему событий;
- ограничивать размер запроса;
- поддерживать rate limiting;
- отбрасывать запрещённые поля;
- не сохранять IP как аналитический payload;
- не экспортировать IP в Desktop;
- разделять данные разных проектов;
- поддерживать retention policy;
- позволять удалять старые raw-события;
- логировать ошибки без записи персональных данных.

## Privacy-by-default правила

```text
не собирать лишние данные;
не использовать персональные идентификаторы по умолчанию;
не отправлять данные авторам BalanceCraft;
не скрывать сетевую активность;
не экспортировать IP;
не хранить raw-логи бесконечно;
не делать обязательную регистрацию.
```

## Не-цели версии 1.5

- BalanceCraft Cloud.
- Централизованный сервер авторов BalanceCraft.
- Обязательная регистрация пользователей.
- Автоматическая интеграция со Steam.
- Маркетинговая аналитика.
- Юридический compliance “из коробки”.
