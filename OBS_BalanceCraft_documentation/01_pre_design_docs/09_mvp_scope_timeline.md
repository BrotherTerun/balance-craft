# 09. Границы MVP, приоритеты и оценка затрат

## Ограничения

- Цель: портфолио-кейс, а не коммерческий SaaS.
- Рабочее время: максимум 48 часов.
- Финансовый бюджет: без новых сервисов и платных инфраструктурных зависимостей.
- Основной продукт: BalanceCraft Desktop.
- Основной режим: Local Mode.

## Приоритеты

### P0 — обязательная база

```text
SQLite вместо MySQL;
новая модель entities / observations / events / metric_runs / metric_values;
локальный импорт JSONL;
профилирование данных;
Binding Wizard без жанровой терминологии;
базовые универсальные шаблоны;
визуализация метрик;
практические выводы;
понятные ошибки.
```

### P1 — портфолио-полировка

```text
демо-проект;
демо-данные;
первый запуск без настройки;
README;
скриншоты;
короткий demo сценарий;
упаковка приложения.
```

### P2 — SDK Lite

```text
Unity SDK;
TrackEvent;
локальная запись JSONL;
event envelope, совместимый с Desktop import;
ограничение кэша;
offline-first поведение;
пример интеграции;
пример демо-логов.
```

Детальные требования к SDK в `08_requirements.md` фиксируют будущую совместимость формата событий. Они не означают, что SDK входит в BalanceCraft 1.5.

### P3 — Self-hosted Server

```text
collector endpoint;
валидация событий;
изоляция проектов;
экспорт JSONL/CSV;
retention policy;
rate limiting;
Docker;
документация;
безопасные настройки по умолчанию.
```

Детальные требования к Self-hosted Collector в `08_requirements.md` описывают будущий серверный компонент. Они не расширяют MVP 1.5 и не меняют local-first приоритет.


## Приоритеты проблем баланса

Расширенная таксономия проблем не равна обязательному объёму MVP. Для 48 часов используется разрез по приоритетам.

### P0 — базовые симптомы

```text
дефицит;
профицит;
инфляция;
плато прогрессии;
перегретая конверсия;
низкая конверсия;
базовая волатильность;
предупреждение о недостатке данных.
```

### P1 — практическое расширение

```text
недостаточные sink-механики;
бутылочные горлышки;
скачки прогрессии;
мёртвый контент;
недоступность операций;
неровный pacing наград;
покрытие анализа по проблемам баланса.
```

### P2 — сложные выводы

```text
доминирующие стратегии;
сравнение альтернативных путей развития;
расширенная нестабильность;
прогноз изменения поведения игрока.
```

## Что входит в BalanceCraft 1.5

| Блок | Статус |
|---|---|
| Desktop app | входит |
| SQLite runtime | входит |
| JSONL import | входит |
| Data profiling | входит |
| Binding Wizard | входит |
| 4 универсальных шаблона | входит |
| Графики | входит |
| Practical insights | входит |
| Базовое покрытие анализа | входит |
| Простой параметрический What-if | входит, если не ломает сроки |
| Demo project | входит |
| README и скриншоты | входит |

## Что не входит в BalanceCraft 1.5

- BalanceCraft Cloud.
- Self-hosted Collector.
- SDK как обязательный компонент.
- Collector endpoint, batch upload, rate limiting и retention policy.
- Полноценная модельная симуляция.
- External simulation adapter.
- ML-интерпретация.
- Автоматическое понимание смысла данных.
- Маркетинговая аналитика.
- Steam/Unity/GameAnalytics интеграции.
- Полноценный BI-конструктор дашбордов.

## Оценка 48 часов

| Блок | Оценка |
|---|---:|
| Финализация документации и проектной рамки | 4–6 ч |
| SQLite-слой и схема | 6–8 ч |
| Миграция импорта | 5–6 ч |
| Миграция расчёта метрик | 5–6 ч |
| Профилирование данных | 4–6 ч |
| Обновление Binding Wizard | 6–8 ч |
| UI-адаптация под срезы анализа | 4–6 ч |
| Простой What-if | 4–6 ч |
| Демо-данные, README, скриншоты | 4–6 ч |
| Резерв на баги | 4–6 ч |

Сумма превышает 48 часов, поэтому нужен жёсткий порядок резки. 48 часов — это не оценка “полной стабильной версии”, а жёсткий лимит на портфолио vertical slice.

## Реалистичная оценка полной стабильной версии

Если делать не только портфолио vertical slice, а устойчивую версию с хорошей обработкой ошибок, аккуратным UI и более спокойным QA, реалистичная оценка выше:

| Блок | Оценка |
|---|---:|
| SQLite-схема, миграции, db layer | 12–16 ч |
| Универсальный import + profiling | 10–14 ч |
| Metric engine + template execution | 16–24 ч |
| Binding Wizard и UI-срезы | 12–18 ч |
| Practical insights + warnings | 8–12 ч |
| Простой What-if + confidence status | 10–16 ч |
| Demo project, README, screenshots | 8–12 ч |
| QA, баги, упаковка | 12–18 ч |

Итого: примерно 80–120 часов.

Для текущей задачи это не отменяет лимит 48 часов. Это фиксирует разницу между:

```text
портфолио-MVP / vertical slice → 48 часов;
стабильная версия для внешнего пользователя → 80–120 часов.
```

## Порядок резки

Если времени не хватает, резать в таком порядке:

1. расширенный What-if;
2. сравнение билдов;
3. импорт CSV/JSON кроме JSONL;
4. расширенные шаблоны;
5. красивые настройки UI;
6. SDK;
7. Self-hosted Collector.

Нельзя резать:

- запуск без MySQL;
- SQLite;
- импорт JSONL;
- карту данных;
- Binding Wizard;
- хотя бы 2–4 шаблона;
- графики;
- демо-проект.

## Definition of Done для 1.5

Версия считается готовой как портфолио-MVP, если:

```text
приложение запускается без MySQL;
локальная SQLite-БД создаётся автоматически;
демо-проект открывается с первого запуска;
JSONL импортируется без ручного SQL;
система показывает карту данных;
можно настроить semantic bindings;
метрики считаются по выбранному шаблону;
формулы не подменяют отсутствующие данные искусственными значениями;
график строится по выбранному срезу;
выводы объясняют основание вывода;
ошибки понятны человеку;
система показывает, если данных недостаточно для части проблем баланса;
данные не отправляются наружу.
```

## Реалистичный целевой результат за 48 часов

Минимальный достойный результат:

```text
BalanceCraft Desktop 1.5 local-only
+ SQLite
+ demo project
+ JSONL import
+ data map
+ universal Binding Wizard
+ 4 metric templates
+ chart dashboard
+ practical insights
+ basic analysis coverage на лету
+ README with screenshots
```

What-if добавляется только если P0 не горит.
