# 17. Implementation checklist

## Назначение

Этот документ превращает feature list в рабочий порядок реализации BalanceCraft 1.5.

Это не календарный план и не обещание уложиться в конкретное количество часов. Это checklist, по которому можно идти во время рефакторинга, вычёркивать задачи и быстро понимать, что уже собрано, а где ещё торчит старый MySQL-хвост.

## Правила работы с чеклистом

1. Идём сверху вниз, если нет веской причины менять порядок.
2. Не начинаем P1/P2, пока не работает соответствующий P0-путь.
3. Любой пункт считается закрытым только после ручной проверки или теста.
4. После каждой фазы проверяем, не вернулась ли жанровая модель `players/sessions/items/skills` как фундамент.
5. Каждый завершённый phase должен оставлять приложение в запускаемом состоянии.
6. Если фаза расползается, режем P1, а не ломаем P0.

## Легенда

```text
[ ] не начато
[/] в работе
[x] выполнено
[!] заблокировано
[-] вырезано из scope
```

# Phase 0 — Подготовка репозитория

Цель: подготовить проект к контролируемому рефакторингу, не ломая текущий прототип вслепую.

## Задачи

- [ ] Создать рабочую ветку рефакторинга, например `refactor/balancecraft-1.5`.
- [ ] Зафиксировать текущую рабочую версию прототипа отдельным commit/tag.
- [ ] Добавить или обновить папку `docs/` актуальным пакетом документации.
- [ ] Добавить новые проектировочные документы `16+` в `docs/`.
- [ ] Проверить, что приложение запускается до начала миграции.
- [ ] Зафиксировать текущие entry points: `main.py`, frontend, pipeline, db init.
- [ ] Составить короткий список файлов, которые точно трогаем первыми.
- [ ] Составить короткий список файлов, которые пока не трогаем.

## Ручная проверка

- [ ] Приложение запускается в текущем состоянии.
- [ ] Есть clean commit перед началом рефакторинга.
- [ ] Понятно, как откатиться.

## Выход фазы

```text
Репозиторий готов к контролируемому рефакторингу.
Есть точка отката.
Есть актуальная документация.
```

# Phase 1 — SQLite core

Цель: заменить внешний MySQL runtime на локальный SQLite foundation.

## Задачи

- [ ] Создать модуль `backend/db.py` или аналогичный единый DB layer.
- [ ] Реализовать функцию открытия SQLite connection.
- [ ] Включить `PRAGMA foreign_keys = ON` для каждого соединения.
- [ ] Определить путь к локальной БД BalanceCraft.
- [ ] Реализовать schema initialization.
- [ ] Создать начальный `schema_sqlite.sql` или миграцию `001_init.sql`.
- [ ] Добавить таблицу `schema_migrations`, если миграции входят в первый проход.
- [ ] Добавить таблицу `app_settings`.
- [ ] Добавить таблицу `projects`.
- [ ] Добавить минимальные индексы для `projects` и будущих events/metrics.
- [ ] Убрать runtime-зависимость от `mysql.connector` из точки запуска.
- [ ] Убрать hardcoded `DB_CONFIG`, root password и `monitor_rpg_model` из runtime.

## Ручная проверка

- [ ] Приложение запускается без запущенного MySQL.
- [ ] При первом запуске создаётся SQLite-БД.
- [ ] Повторный запуск не ломает БД.
- [ ] Ошибка создания БД показывается понятным сообщением.

## Выход фазы

```text
BalanceCraft имеет локальное SQLite-хранилище и больше не требует MySQL для запуска.
```
