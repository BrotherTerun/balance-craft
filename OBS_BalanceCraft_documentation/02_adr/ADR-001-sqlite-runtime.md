# ADR-001. SQLite вместо MySQL в runtime

Дата: 2026-07-02  
Статус: accepted

## Контекст

Desktop-версия BalanceCraft должна запускаться как локальное приложение без внешней инфраструктуры. MySQL создаёт лишние требования: установленный сервер, служба, root-пароль, localhost, ручная настройка, проблемы прав Windows и сложная диагностика.

Для портфолио-MVP это ломает главный пользовательский сценарий: скачал, запустил, увидел пользу.

## Решение

MySQL удаляется из runtime BalanceCraft Desktop.

Основная локальная БД версии 1.5 — SQLite-файл в пользовательской папке BalanceCraft.

Целевой путь:

```text
Документы/BalanceCraft/balancecraft.db
```

## Альтернативы

### Оставить MySQL

Плюсы:

- часть кода уже написана;
- привычная реляционная модель.

Минусы:

- сложный запуск;
- внешняя служба;
- root-пароль;
- плохой UX для инди-пользователя;
- не подходит для portable/demo-приложения.

### Использовать JSON-файлы

Плюсы:

- просто читать и писать;
- нет БД.

Минусы:

- сложнее индексировать события;
- хуже для 100k+ событий;
- неудобно хранить metric runs, scenarios и bindings.

## Последствия

Плюсы:

- приложение запускается без внешней СУБД;
- проще упаковка;
- проще демо;
- меньше технических ошибок у пользователя;
- БД можно хранить рядом с проектными данными.

Минусы:

- нужно переписать SQL-запросы;
- заменить `INFORMATION_SCHEMA` на `PRAGMA`;
- адаптировать placeholders с `%s` на `?`;
- пересобрать schema init и migrations.
