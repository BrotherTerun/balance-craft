# ADR-003. Entity / Observation вместо Player / Session

Дата: 2026-07-02  
Статус: accepted

## Контекст

Старая модель была завязана на игроков, сессии, предметы и навыки. Это сужает BalanceCraft до RPG/progression analyzer и мешает анализировать другие системы: стратегии, survival, idle, roguelike, management, симуляторы, внутренние системные параметры.

## Решение

В новой модели ядро строится вокруг универсальных понятий:

```text
project
entity
entity_type
observation
event
attribute
parameter
metric
binding
scenario
```

`player`, `session`, `item`, `skill` остаются допустимой пользовательской семантикой, но не являются фундаментальными таблицами ядра.

## Альтернативы

### Оставить players/sessions

Плюсы:

- меньше переписывать;
- текущий UI уже работает.

Минусы:

- жанровая привязка;
- плохая масштабируемость концепции;
- сложнее объяснить продукт как универсальный инструмент.

### Сделать отдельные таблицы под жанры

Минусы:

- быстро разрастается;
- требует поддерживать множество схем;
- противоречит late semantic binding.

## Последствия

Плюсы:

- продукт становится жанрово независимым;
- проще импортировать разные структуры данных;
- параметры можно назначать любой сущности;
- сессия становится одним из типов observation.

Минусы:

- нужно переписать часть UI;
- нужно обновить данные демо;
- старые метрики нужно обобщить.
